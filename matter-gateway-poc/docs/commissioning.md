# 커미셔닝(Commissioning)이란

한 줄로: **새 기기를 "우리 집 네트워크"에 가입시키고 "우리 컨트롤러만 조작할 수 있게" 열쇠를 심는 과정.** 블루투스 기기 페어링과 비슷하지만, 네트워크 가입 + 신원 확인 + 권한 부여까지 한 번에 한다.

## 비유
새 직원(기기)이 회사(게이트웨이/패브릭)에 입사하는 절차.
1. 신분증 확인: 기기 QR 코드의 비밀번호(셋업 코드)로 "내가 그 기기 주인이 맞다"를 증명 (PASE).
2. 위조품 검사: 기기가 CSA 인증 제조사의 정품 인증서를 가졌는지 확인 (Device Attestation).
3. 사원증 발급: 우리 패브릭 전용 인증서(NOC)를 기기에 설치. 이후 이 패브릭의 컨트롤러만 명령 가능.
4. 사무실 와이파이 알려주기: Thread 네트워크 자격증명(Operational Dataset)을 기기에 전달 → 기기가 Thread 망에 가입.
5. 정식 통신 시작: 이제부터는 BLE 가 아니라 Thread/IP 로 암호화 통신 (CASE).

## 실제 흐름 (우리 게이트웨이 기준)
```
앱: QR 스캔 → "MT:Y.K90..." 코드 전송
          ↓ (클라우드 MQTT  gw/<id>/pairing/start)  ※ WebSocket 릴레이로 대체: relay-v2 req POST /siot-app/api/v1/pairing (docs/relay-protocol.md)
게이트웨이: 1) BLE 로 광고 중인 기기 발견
           2) 셋업 코드로 PASE 세션
           3) 인증서 검사(DCL/PAA 루트, 인터넷 필요)
           4) 우리 패브릭 인증서 설치
           5) Thread 데이터셋 전달 → 기기가 OTBR 의 Thread 망에 가입
           6) Thread/IP 로 CASE 세션 → 인터뷰(어떤 클러스터가 있는지 읽기)
          ↓ (pairing/event: done + 디바이스 모델)
앱: 기기 목록에 표시
```

## 용어
- **패브릭(Fabric)**: 한 컨트롤러(또는 생태계)가 관리하는 보안 영역. 기기 하나가 최대 5개 패브릭(Apple/Google/우리)에 동시에 속할 수 있음 → "멀티 어드민".
- **셋업 코드**: QR(`MT:...`) 또는 11/21자리 수동 코드. 기기 박스/본체에 인쇄. 한 번 쓰면 기기가 광고를 멈추므로, 다른 생태계에 추가하려면 컨트롤러가 "커미셔닝 창"을 열어 새 코드를 발급(`open_commissioning_window`).
- **Operational Dataset**: Thread 망의 비밀(네트워크 키, PAN ID, 채널 등)을 hex 로 묶은 것. OTBR 에서 `ot-ctl dataset active -x` 로 얻음. 컨트롤러에 한 번 등록(`set_thread_dataset`)해 두면 이후 커미셔닝 때 자동 전달.
- **보더 라우터(OTBR)**: Thread 망과 IP(LAN) 망 사이의 다리. ZBT-2 가 무선부, Pi 가 두뇌.
- **인터뷰**: 커미셔닝 직후 기기의 엔드포인트/클러스터/속성을 모두 읽어 모델을 만드는 단계.

## 왜 게이트웨이가 커미셔닝하게 하나 (폰이 아니라)
- 폰이 하면 폰의 패브릭(Apple/Google)에 들어가고, 우리 게이트웨이는 2차 관리자로 다시 추가해야 함.
- 게이트웨이가 하면 패브릭 열쇠가 게이트웨이에만 있어 보안 경계가 단순하고 앱은 코드만 전달하면 됨.
- 단점: 기기가 게이트웨이 BLE 범위(약 10m) 안에 있어야 함. 멀리 설치할 기기는 게이트웨이 옆에서 먼저 등록 후 옮기면 됨.
